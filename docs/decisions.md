# Журнал решений и результатов

Записывается после каждого шага: что сделали, почему, чем проверили, что получилось (включая неудачи).

## 2026-11-09 — версия 1: демо «вопрос → режим»
- Цепочка: разбор вопроса → расчёт режима → нейросеть-классификатор риска → оптимизация.
- Вывод после самооценки: классификатор дублирует физический расчёт и выдаёт «вероятность», которая
  на самом деле — доля аварийных случаев в синтетической выборке. Направление изменено.

## 2026-11-09 — версия 2: «риск на завтра»
- ML перенесён туда, где он нужен: прогноз нагрузки по погоде (физика здесь не помогает).
- Добавлены DLR, N-1 по часам, превентивная оптимизация.
- Найдено: при +46 °C нейросеть занижала пик (189 против 221 МВт), т. к. в истории не было таких
  температур. Исправлено расширением истории; в интерфейсе — предупреждение об экстраполяции.

## 2026-11-09 — версия 3: исправления по аудиту
- Независимая проверка ядра (Python, scipy): совпадение до 0,002 В на 368 режимах; 32 случая P–V подтверждены.
- Несходимость больше не трактуется как коллапс: три ступени решения + метод продолжения + проверка
  вырождения якобиана.
- Острова с местной генерацией (ГТЭС Жанаозен, ГТУ Жетыбай) и АЧР при дефиците.
- **Собственная ошибка:** интервал P10–P90 подбирался на тех же данных, на которых проверялось покрытие.
  Исправлено: калибровка и проверка на разных неделях. Покрытие: 78–80 % при обычных температурах,
  74 % при ≥ 40 °C (мало данных).
- Удалён неиспользуемый классификатор.

## 2026-11-10 — шаг 1.3: сверка с pandapower
- **Среда:** Python 3.13.17 в `.venv`, pandapower 3.5.6, numpy 2.4.6, pandas 2.3.3; Node.js 26.13 для `export.js`.
  На Python 3.15 зависимости не ставятся: у pandas нет готовой сборки, сборка из исходников падает.
  numba не установлен — pandapower работает медленнее, на результат это не влияет.
- **Запуск:** `node validation/export.js` → 400 сценариев (368 сошлось, 32 — предел P–V, 0 — numerical),
  затем `python validation/compare_pandapower.py`.
- **Результат:** 368 режимов сравнено, ошибок pandapower 0, вне допуска 0.
  Макс. |ΔU| = 1,76e-8 о.е., |ΔP| = 1,48e-6 МВт, |ΔQ| = 2,33e-6 Мвар; генерация: |ΔP| = 1,18e-6 МВт, |ΔQ| = 2,33e-6 Мвар.
  Запас до допуска (1e-4 о.е., 0,01 МВт) — больше 4 порядков. Построитель `twin/pp_model.py` заработал с первого запуска.
- **Что это проверяет и что нет:** pandapower считает сам (NR с плоского старта, пределы Q включены),
  но модель строится из тех же `data/network.yaml`, а распределение АЧР по островам берётся из ядра.
  Значит, подтверждены уравнения и решатель, но не параметры сети (они по-прежнему допущения)
  и не логика АЧР. Режимы на пределе P–V pandapower не сравнивались.
- **Прочие проверки:** `validation/check.py` — 368/368, |ΔU| 1,76e-8 о.е.; `validation/check_pv.py` — 32/32 случая
  P–V подтверждены (3 из них — решение при 100 % существует только с нарушением пределов Q);
  pytest — 11 тестов, все проходят (раньше 3 пропускались из-за отсутствия `cases.json`).

## 2026-11-10 — шаг 2.1: погода Open-Meteo
- **Сделано:** `data/weather_points.yaml` (координаты Актау, Жанаозена, Бейнеу — *источник*: GeoNames;
  привязка узлов сети к точкам — *допущение*), `twin/weather.py` (загрузка, кэш в CSV, работа без сети,
  без подмены синтетикой), `data/weather/archive` и `data/weather/day_ahead` — 2023–2025 по трём точкам (~10 МБ),
  `tests/test_weather.py` (12 тестов, без интернета), `validation/check_weather.py`.
- **Отступление от плана:** для ошибки прогноза взят Previous Runs API (`*_previous_day1` — прогноз,
  выпущенный за сутки), а не Historical Forecast API: последний склеивает первые часы каждого выпуска
  и прогнозом на сутки вперёд не является.
- **Найдено по пути:** расстояния от Форт-Шевченко, Жетыбая и Шетпе до точек сначала были написаны по памяти
  (Шетпе «~140 км» — на деле 95 км) — исправлено по координатам GeoNames. Жетыбай почти равноудалён от
  Жанаозена (67 км) и Актау (75 км): привязка к Жанаозену почти произвольна.
- **Данные:** архив ERA5 — 26 304 часа на точку, пропусков 0, значений вне пределов 0. Ячейки ERA5:
  Актау 43,75/51,25 (≈11 км от города, у берега), Жанаозен 43,25/52,75, Бейнеу 45,25/55,25.
  Прогноз на сутки: T есть с 2023 г. (пропуск 30.12.2023–19.01.2024), остальные величины — только
  с 19.01.2024 17:00; итого 17 095 полных часов из 26 304. Пропуски не заполнялись.
- **Время:** местное UTC+5. Радиация — среднее за предыдущий час (максимум среднего — строка 14:00,
  солнечный полдень в Актау ≈ 13:35 местного). В `day.js` полдень принят 12:30 — это допущение не подтвердилось.
- **Сверка ERA5 со станциями NOAA ISD (2023 — 24.08.2025, дальше ISD рядов нет):**
  | станция | T: смещение / MAE / r | T при ≥ 35 °C: смещение | ветер: смещение / MAE / r |
  |---|---|---|---|
  | Актау-город WMO 38111 (SYNOP, 11 км) | +0,18 / 1,23 °C / 0,989 | −1,54 °C (n=50) | +1,14 / 1,54 м/с / 0,78 |
  | Аэропорт Актау UATE (METAR, 22 км) | +0,26 / 1,34 °C / 0,988 | −1,78 °C (n=336) | −0,17 / 1,40 м/с / 0,73 |
  | Бейнеу WMO 35927 (SYNOP, 12 км) | −0,12 / 0,89 °C / 0,996 | −0,42 °C (n=328) | +1,25 / 1,62 м/с / 0,80 |
  Сдвиг по времени с наибольшей корреляцией — 0 ч на всех станциях (часовой пояс обработан верно).
  **Выводы:** у Актау ERA5 занижает жару на 1,5–1,8 °C — это важно для пика нагрузки и DLR;
  ветер ERA5 выше синоптических станций на 1,1–1,3 м/с (DLR по ERA5 был бы оптимистичен).
  ERA5 усваивает эти же сводки, поэтому сверка не полностью независима.
- **Прогноз на сутки против станций:** Актау T MAE 1,70 °C, ветер MAE 1,18 м/с; Бейнеу T 1,61 °C, ветер 1,23 м/с.
  Против ERA5: T MAE 1,43–1,56 °C, радиация днём MAE 41–45 Вт/м².
- **Не получилось:** Жанаозен со станцией не сверен — в ISD станция UZEN есть только за 1981–1986,
  ближайшая действующая (Аккудук) в 110 км. **Неудачная попытка:** сначала сверка шла по Meteostat;
  оказалось, что его почасовые ряды дополнены модельными данными (у Бейнеу 24 значения в сутки при
  8 сводках SYNOP), а флаги источника в выгрузке кончаются на 2022 г. По Meteostat ветер Бейнеу давал
  смещение +0,02 м/с, по первичным сводкам — +1,25 м/с: загрязнённые данные дали бы ложный вывод.
  Источник заменён на NOAA ISD.
- **Прежние допущения `MONTH_TYPICAL` (day.js) против ERA5 Актау:** Tmax ошибались от −2,8 °C (март)
  до +1,1 °C (июнь), Tmin — от −2,0 °C (ноябрь) до +1,2 °C; весной и осенью допущения холоднее реальности,
  ветер завышен на 0,1–1,2 м/с.
- **Проверки:** `check_weather.py` — целостность в порядке, признаков сбоя нет; `check.py`, `check_pv.py`,
  `compare_pandapower.py` — без изменений; pytest — 23/23, пропусков нет.
- **Среда:** при подготовке поставлены Node.js 26.13 и Python 3.13 (см. шаг 1.3).
- **Дальше:** погода к расчётам не подключена — модель нагрузки и DLR всё ещё на синтетике (шаги 3.2, 3.3).


## 2026-11-12 — шаг 2.2: схема сети из открытых источников
- **Решения пользователя:** условная `data/network.yaml` не меняется (эталон сверок JS ↔ Python ↔ pandapower),
  новая сеть — отдельный файл `data/network_real.yaml`; 220 кВ собирается, но не считается (шаг 2.4);
  в расчёт идут **только линии с тегом voltage=110000** (вариант A) — линии без тега напряжения не
  «дорисовываются» как 110 кВ.
- **Сделано (по пунктам плана, каждый — отдельный коммит):**
  1–2. `twin/osm.py`: снимок Overpass `data/osm/power_2026-11-10.json` (база OSM 2026-11-10T16:07Z, ODbL),
     обработка без сети → `data/network_sources/osm_segments.csv`, `osm_lines.csv`, `osm_substations.csv`.
     В снимке 267 участков линий: 110 кВ — 56 (857 км по трассе), 220 кВ — 12, 35 кВ — 38,
     **без тега напряжения — 161 (1 192 км)**; 100 ПС/станций, имя только у 3.
  3. `data/network_sources/documents.yaml` — 58 фактов из открытых документов с URL, страницей, цитатой
     и уверенностью: годовые отчёты АО «МРЭК» 2019–2024, перечень закупок МРЭК 2021, отчёт ККС 2019,
     KEGOC, заявление о намечаемой деятельности ГПЭС Жанаозен, новости о станциях; 12 пунктов `not_found`.
  4. `twin/substation_match.py` → `substation_ids.csv`: у каждой ПС уверенность и основание.
     Высокая (имя в OSM) — 3, средняя (класс напряжения OSM + ПС из документа у названного посёлка,
     единственный кандидат) — 4: ПС 220 «Бейнеу», УРПС 220/110/35/10 «Каражанбас», ПС 220/110/10 «Узень»,
     ПС 110/35/6 «Бейнеу»; низкая (только близость к посёлку ≤ 5 км, *допущение*) — 56; не опознана — 37.
  5. `twin/build_real.py` → `data/network_real.yaml` (шапка ODbL 1.0; пометки по полям в `marks`;
     доли источников в `summary`; 220 кВ — `inventory_220kv`; линии без тега — `not_modelled`).
     Сеть 110 кВ по тегам — **2 острова**: Бейнеу (646 км, 22 шины) и Бузачи/Каражанбас (210 км, 11 шин);
     33 шины (8 ПС, 2 ПС 220/110, 18 ответвлений, 5 обрывов линий), 43 линии = 59 цепей.
     Питание от ПС 220/110 — эквиваленты (*допущение*): Бейнеу — балансирующий (предел 500 МВт,
     мощность АТ не найдена), Каражанбас — 138 МВт (АТ 150 МВА — *источник*, × cos φ 0,92 — *допущение*).
     Двухцепная линия — две линии (ядро не меняется); число цепей из тега circuits — *источник*,
     из cables или без тегов — *допущение*. Нагрузка — поровну между 8 ПС (*допущение*, шаг 2.3).
  6. `twin/powerflow.py`: балансирующий генератор — по флагу `slack: true` вместо id «G1».
  7. `validation/compare_network.py` → `validation/compare_network_report.md` (см. ниже).
  Дополнительно: проверочная карта `validation/network_map.html` (`validation/make_map.py`).
- **Доли «источник» в network_real.yaml:** длины 100 % (по км цепей), цепи 85 %, **провода 0 %,
  нагрузки 0 %, генерация 0 %** (по МВт; места эквивалентов — 100 %), названия ПС — 3 из 10.
- **Сравнение с условной сетью:** ПС у места есть в OSM для 7 из 8 узлов («Промзона» — место не определено);
  в модель вошла только Бейнеу. Из 11 условных линий связи в модели нет ни у одной; путь в OSM по 110 кВ
  и линиям без тега — у двух (МАЭК–Шетпе 99,9 км против условных 95; Жетыбай–Жанаозен 65,1 против 60),
  оба целиком по линиям без тега. Жанаозен–Бейнеу и Шетпе–Бейнеу в OSM связаны только через 220 кВ;
  МАЭК–Актау, Актау–Жетыбай, Актау–Форт-Шевченко, Шетпе–Форт-Шевченко не связаны вообще.

- **Проверки:** `validation/check_network_real.py` — ядро и pandapower совпадают в 3 режимах

- **Что не получилось / ограничения (важно для выводов):**
  - **Сетей Актау, Жетыбая и Жанаозена в модели нет**: в OSM у их линий нет тега напряжения.
    С тегом 110 кВ в OSM 857 км, у МРЭК — 1 526 км ВЛ 110 кВ (отчёт 2024). Модель покрывает примерно
    половину сети 110 кВ и не содержит главных узлов нагрузки и генерации (МАЭК).
  - Марки проводов существующих ВЛ 110/220 кВ не найдены ни в одном документе (только АС-300/43 у проектной

  - Генерация МАЭК (ТЭЦ-1/2, ТЭС) взята из Википедии (баланс 2014 г.); сайт maek.kz отдаёт 404.
