# MANGYSTAU AI DIGITAL TWIN

Прототип интеллектуального цифрового двойника региональной электрической сети Мангистауской области.
Задача: заранее, на сутки вперёд, находить часы и отказы оборудования, при которых режим сети станет
недопустимым, и предлагать превентивные меры.

**Цепочка:** погода → прогноз нагрузки (ML) → динамический допустимый ток линий (DLR) →
проверка N-1 по каждому часу → превентивная оптимизация → корректирующие действия.

## Статус

Прототип. Расчётные методы реальные и проверены, **исходные данные условные** (см. ниже).
Корректное название на текущем этапе — *прототип* цифрового двойника, а не цифровой двойник реальной сети.

| Компонент | Состояние |
|---|---|
| Расчёт режима (AC, Ньютон–Рафсон → демпфированный Ньютон → метод продолжения) | реализован, независимо проверен |
| Острова с местной генерацией, АЧР | реализовано |
| Предел передаваемой мощности (P–V), отделение от численной несходимости | реализовано, проверено |
| DLR (упрощённый тепловой баланс IEEE 738) | реализовано |
| Прогноз нагрузки (нейросеть vs линейная модель) | реализовано на **синтетической** истории |
| N-1 по 24 часам (336 расчётов), превентивные меры, ограничения скорости набора | реализовано |
| Схема сети Мангистау | **условная**: 8 узлов 110 кВ, 11 линий, 3 источника |
| Реальная погода (Open-Meteo: архив ERA5 2023–2025, прогноз) | загружается (`twin/weather.py`), сверена со станциями; **в расчёты ещё не подключена** |
| Реальная нагрузка | **нет** |
| Трансформаторы, динамика, релейная защита | **не моделируются** |

## Структура

```
data/           параметры сети (network.yaml), точки погоды (weather_points.yaml) — у каждого значения пометка
                «источник» или «допущение»; data/weather/ — почасовая погода Open-Meteo (CSV)
twin/           Python-ядро: network.py — загрузка данных, powerflow.py — расчёт режима, pp_model.py — модель в pandapower,
                weather.py — погода Open-Meteo
tests/          автотесты pytest
core_js/        расчётное ядро (JavaScript): engine2.js — режим сети и оптимизация, day.js — сутки вперёд
validation/     независимая проверка ядра (Node.js + Python/numpy/scipy) и сверка с pandapower
web_prototype/  веб-прототип интерфейса (один HTML-файл, открывается в браузере)
docs/           аудит, план работ, журнал решений
```

## Как запустить

**Веб-прототип:** открыть `web_prototype/index.html` в браузере.

**Версия Python: 3.13** (проверено на 3.13.17). На Python 3.15 зависимости не ставятся:
у pandas нет готовой сборки под эту версию. На Windows окружение создаётся так: `py -V:3.13 -m venv .venv`.

**Все проверки одной командой** (Windows: `py` вместо `python`), из корня репозитория:

```
python -m pip install -r requirements.txt
python -m pytest
```

Тест сверки с pandapower запускается, только если pandapower установлен; без Node.js тесты,
которым нужны результаты JS-ядра, пропускаются.

**Проверка ядра по отдельности** (нужны Node.js и Python 3 с numpy и scipy):

```
node validation/export.js
python validation/check.py
python validation/check_pv.py
python validation/compare_pandapower.py   # нужен pandapower
python validation/check_weather.py        # погода: целостность и сверка со станциями NOAA ISD (нужен интернет при первом запуске)
```

Результаты на 09.11.2026:
- аналитический якобиан совпадает с конечными разностями (расхождение 4e-6 при элементах до 40);
- 368 сошедшихся режимов из 400 совпадают с независимым решателем: |U| до 0,002 В, потоки до 1e-6 МВт;
- небаланс мощности < 1e-6 МВт;
- все 32 случая «предел P–V» подтверждены.

Ограничение проверки: оба решателя используют одну модель сети. Проверена правильность решения
уравнений, а не соответствие реальной энергосистеме.

## Что условно

- Названия подстанций настоящие, но топология, длины и марки проводов, нагрузки и мощности станций — допущения.
- История нагрузки — синтетическая (2 года по часам), поэтому точность прогноза (MAPE ≈ 2 %) показывает
  работоспособность метода, а не точность на реальных данных.
- Погода в веб-прототипе и в `core_js/day.js` — по-прежнему сценарий, а не прогноз: реальные данные
  Open-Meteo загружены (шаг 2.1), но к расчётам ещё не подключены.
- «Риск» — число отказов, после которых режим недопустим, а не вероятность аварии.

## Источники данных

- **Погода:** [Open-Meteo](https://open-meteo.com/) — архив ERA5 (Hersbach et al., 2020), прогнозы, прогнозы прошлых выпусков.
  Лицензия [CC BY 4.0](https://open-meteo.com/en/licence); бесплатный API — для некоммерческого использования.
- **Координаты точек:** [GeoNames](https://www.geonames.org/), CC BY 4.0.
- **Наблюдения станций (только для проверки):** NOAA NCEI, [Integrated Surface Database](https://www.ncei.noaa.gov/products/land-based-station/integrated-surface-database).
